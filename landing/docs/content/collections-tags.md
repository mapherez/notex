# Collections & tags

Collections and tags serve different organizing needs. Use a collection for a note's main home, and tags for connections that cross those homes.

## Collections

A note can belong to a collection, such as **Work**, **Recipes**, or **Study**. Create and manage collections in the organization pages, then assign one from the note's collection selector.

Keep the names meaningful for the way you browse. A handful of useful collections is often easier to maintain than a separate collection for every small topic.

## Tags

A note can have multiple tags. For example, a note in **Work** could have **reference**, **meeting**, and **planning** tags. Another collection can use those same tags.

Create tags from the Tags page, choose their colors, and apply them to notes. Existing colors help make labels recognizable while browsing.

## Use them together

Imagine a collection called **Cooking** and tags called **quick**, **vegetarian**, and **dessert**. The collection answers where the note belongs; the tags answer which kinds of notes it relates to.

Use the collection and tag filters in the note list to narrow your view. [Search](search.md) also matches collection and tag names.

## Rename or delete labels

You can rename tags and collections as your library changes. Deleting a tag removes that tag from the notes using it. Deleting a collection leaves its notes without that collection.

Deleting either label does not delete the notes themselves.

## Importing organization

An individual-note import matches the note's organization against your existing library. Tags, a collection, or linked notes that cannot be matched can be omitted, and the import result reports what was skipped.

A full-workspace import is different: it restores the exported workspace by replacing the current library. Read [the import guide](import-export.md) before using it.
